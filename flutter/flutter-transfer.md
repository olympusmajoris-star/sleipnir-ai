# Approved studio surface for Flutter

`AsgardStudioSurface` is a reusable Flutter widget that displays the same web scene renderer used by the studio. It loads approved release snapshots through the immutable `runtime/transfer-20261114-v1/app-runtime.html` build; it never reads a draft or accepts a preview mode. This is a WebView integration, not conversion of JavaScript artwork into native Flutter drawing code.

## What is implemented

- Page/design/store identity validation, including every current page and all five store-list types.
- Approved-release selection; omit `releaseId` to follow the latest approved release, or supply a UUID to pin an approved release.
- HTTPS-only runtime at the existing studio origin. Editor top-level navigation, arbitrary URLs and unsafe schemes are blocked.
- Explicit real-contact input. Empty input clears contacts; test contacts are never generated by the widget.
- Navigation, product and contact callbacks with validated structured messages.
- Inline video configuration on supported native platforms, loading/error/retry UI, readiness timeout, lifecycle notifications and stale-load guards.
- No Supabase secrets, session tokens or publication credentials in the widget.

## Parameters and actions

| Parameter | Meaning |
| --- | --- |
| `width`, `height` | FlutterFlow widget dimensions. |
| `page` | `raven`, `home`, `shome`, `browse`, `store`, `swap`, `ads`, `shoppost`, `deals`, `share`, `convo`, `heimdall`, `track` or `navigation`. |
| `designId` | `raven`, `navigation`, `page_<page>`, `page_store_<store UUID>` or `page_browse_<type>`, matching the page. |
| `storeId` | Required only for store pages. |
| `releaseId` | Optional approved release UUID. |
| `contactsJson` | Optional JSON array with `id`, `name`, `msg`, `unread`, `bust`, `face`, `counts`. No auth material is accepted or forwarded. |
| `onNavigate(target, storeId, pageType)` | Route to the actual app page. Empty store/type strings mean not applicable. Browse events preserve `pageType`. |
| `onProductTap(productId, storeId)` | Open the app's actual product action using stable IDs. |
| `onContactTap(contactId)` | Open the app's actual contact/conversation action. |

Example: Publix Island Walk uses page `store`, design `page_store_189581c9-d728-4e5d-9e02-ae4de19a15af`, store `189581c9-d728-4e5d-9e02-ae4de19a15af`. Retail browsing uses page `browse`, design `page_browse_retail`; the widget adds `type=retail` automatically.

The callback only requests an action. Existing authenticated app code must perform navigation, messages, purchases, cart operations, delivery tracking and other real behavior. Without a callback, the widget shows an unconnected-action notice; it does not simulate a successful action. The renderer also receives callback capability flags for its own notices.

## Runtime handshake, version 1

Runtime sends JSON to `AsgardBridge.postMessage`:

```json
{"v":1,"type":"ready","design":"raven"}
{"v":1,"type":"navigate","target":"store","storeId":"189581c9-d728-4e5d-9e02-ae4de19a15af"}
{"v":1,"type":"navigate","target":"browse","pageType":"retail"}
{"v":1,"type":"product","productId":"9d5102f3-acd7-48e7-adc8-fc4156aacc66","storeId":"189581c9-d728-4e5d-9e02-ae4de19a15af"}
{"v":1,"type":"contact","contactId":"real-contact-id"}
{"v":1,"type":"error","message":"No approved design is available."}
```

Only send `ready` after the approved design and renderer have loaded, not merely when the HTML document finishes. Dart then invokes `window.AsgardApp.setContext({v:1,contacts:[],capabilities:{navigate:false,product:false,contact:false}})`. `onPageFinished` attempts this handshake as well so contacts can be installed before rendering. Subsequent contact changes repeat it. There is no draft data in the context.

`window.AsgardApp.setActive(boolean)` pauses/resumes the scene when the app goes into the background or returns. Approved-release refresh belongs in the runtime; the widget does not read the design database itself.

## Dependencies and target checks

The following mutually compatible versions were checked against their official package metadata on 2026-11-14:

```yaml
dependencies:
  flutter:
    sdk: flutter
  webview_flutter: 4.14.1
  webview_flutter_android: 4.12.0
  webview_flutter_wkwebview: 3.25.1
```

Together these require Flutter 3.38.0 or newer and Dart 3.10.0 or newer. **The actual FlutterFlow project's SDK and lockfile have not been supplied or verified.** Resolve against that project before installation; retain its generated lockfile. These pins deliberately do not select the newest Android/iOS implementation packages, which require newer Flutter versions.

The package supports Android (SDK 24+), iOS (13.0+) and macOS (10.15+). It does not support Flutter web or Windows/Linux desktop. Browser builds show an explicit unsupported message, not an empty WebView or a false successful preview. Web support would need a separate tested iframe adapter or another compatible package.

## Verification performed

- The complete widget parses through the official Dart 3.14 formatter.
- The actual pure-Dart contract code is extracted from the widget by `run_contract_tests.py`, analyzed with the standalone Dart analyzer and exercised by `contract_test.dart`.
- **68 checks passed**, covering the immutable renderer URL, document mappings, approved-only query construction, pinned releases, correct browse types, trusted navigation, unsafe URL rejection, message validation, ready-event design identity, stable product/store identity, input bounds and clearing demo contacts.
- Flutter framework/widget compilation, Android/iOS build, FlutterFlow compilation, live app routing and visual equivalence have **not** passed yet.

Local Flutter SDK initialization was attempted once. Automatic approval review rejected it because it attempted to contact a link-local cloud metadata service, which could expose instance metadata or credentials. The rejected initialization was not retried. The subsequent formatter/analyzer/contract checks used the standalone Dart executable directly and did not initialize Flutter.

To repeat the allowed pure-Dart checks, run `python run_contract_tests.py /path/to/dart`. This does not call the Flutter tool, download packages or access network services.

## Release and original-app boundaries

- The runtime must fail closed if there is no approved release. Never fall back to `studio_designs`, local editor storage or test/demo data.
- The widget hardcodes renderer build `transfer-20261114-v1`, and approvals must reference that build. A release for another renderer build must be rejected with an upgrade notice rather than silently loading different code. Future renderer features require an explicitly installed app-code upgrade; approved design settings within this build can update without repasting Dart.
- This surface does not replace the native cloud-messaging widget or its authenticated backend. The existing original Dart implementation must remain the authoritative baseline until parity is demonstrated.
- Draft edits, widget download and preview must never perform publication. Danny's explicit approval is a separate authenticated operation.
