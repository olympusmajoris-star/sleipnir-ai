# Cloud footage and object construction

Use Messages & alerts → Construction & cloud motion in the existing workshop. The saved document is `studio_designs/effects_convo`. This editor starts from the supplied original Raven's construction duration, material layout and cloud probabilities. It uses the existing Earth poster and cloud assets in its previews. It does not modify the installed Raven.

## Cloud video workflow

1. Choose a shared clip or open a local file. Select Clip editor.
2. Set start/end, crop and color. Choose background color removal and edge softness. Choose forward/reverse looping, frame rate and quality. The source remains intact. Regular cropped WebM downloads are silent and retain the background; transparent native clouds use Prepare cloud for app.
3. Prepare a slice of up to 30 seconds. Local input is uploaded to the existing shared studio area. Preparation is an owner-only `cloud_prepare` job. Connector v1.3 needs installed FFmpeg with `libwebp_anim`; it can prepare clouds with the retailer collector closed. No PC worker was registered at verification, so queued work waits for a connection.
4. Refresh prepared clouds and inspect the animated result. Choose your-message, their-message or one of three variation slots. Use the prepared result in that slot, or import an already prepared animated WebP. Assignment validates changing frames, 640 × 426 dimensions and a 25 MB limit, then preserves and verifies an immutable SHA-256 asset.
5. Adjust the selected cloud's speed and break-off sampling area. Save shared settings. Export the complete separate `AsgardRavenEffectsTest` widget from the supplied original Raven. Actual FlutterFlow/device behavior must pass before a production change. Retain the working Raven; a Studio save alone does not replace app footage.

The five slots feed the original renderer's message edges, background clouds and offshoot sampling. They are shared sources, not five independent overlay tracks. Existing terrain tracking, white text, ground shadows, contact/message backend and sender behavior are retained.

## Behavior and construction controls

Cloud controls cover interval and timing jitter; repeatable random seed; small/medium probabilities and size variation; attach, drift, dissolve and merge timing; dissolve/absorption chances; speed, wandering and rotation. Construction controls cover duration, rows/columns, layer separation, travel distance, line width, measuring guides and drawing/material colors. Native exports patch those actual original behaviors. Existing day/night ground speed, message spacing/shadows and ambient cloud controls remain under Original app controls.

The browser's construction camera is for authoring preview only. Cloud movement preview is illustrative; native merging, terrain interaction and message behavior still need a device check. Source footage runs through a transparent animated WebP conversion for the native decoder; raw MP4 is not injected into that decoder.

## Reuse and recovery

Undo/redo, named looks, locks, saved slices, original-cloud restoration and settings download are available. Save uses the previously read `updated_at` value and rejects a stale overwrite. Unsaved local clips stay in this browser until uploaded. The original footage stays intact. Shared source/widget inventories contain metadata only; full private native source is not in the public repo.

## Verification

A moving synthetic cloud clip converted to a 640 × 426 animated WebP with 29 changing frames, 3.75 seconds and alpha ranging from 0 to 255. A static one-frame WebP is rejected because the existing native decoder requires animation. Cloud job acceptance, owner claim/lease and cross-user isolation passed a transaction test; every test row was rolled back. Default and custom-cloud native exports parsed with the official Dart formatter, with embedded original assets preserved. These checks are not a FlutterFlow compile/device test or a Windows round trip.
