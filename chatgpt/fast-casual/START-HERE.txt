SLEIPNIR FAST-CASUAL MENU BOARDS - JOB FOR CHATGPT
Written 2026-11-26. Back to the main file: https://olympusmajoris-star.github.io/sleipnir-ai/chatgpt/START-HERE.txt

1) WHAT DANNY WANTS
Every fast-casual store gets in-store digital menu boards like the Subway boards in his video: a row of wide TV
screens mounted edge to edge above the counter, each screen one or two menu categories, bright and clean, with big
appetizing food photos. Same idea for every store, but each brand looks like ITS OWN brand (its real colors, type
feel and food), so no two stores look the same.

What the Subway screens show, left to right: FRESH VALUE (yellow price-burst deal badges, "Meal of the Day" with a
drink and chips), MAKE IT A MEAL (meal add-on: drink, chips, cookie), DELI CLASSICS, CLUBS, CHICKEN, ITALIANS,
CHEESESTEAKS, plus one full-photo promo screen. Each screen: light blue-white background, a bold condensed green
category heading top-left, one large hero sandwich photo, item names in 2-3 columns with a small description line and
6-inch / footlong prices, small product photos (drinks, chips, cookies), and a bright green callout strip along the
bottom ("Make ANY footlong a meal", "Veggie Delite").

2) HOW TO MAKE THE BOARDS (same rule as the drive-thru boards)
- Render each screen as one landscape image, 1536 x 1024 (or wider 16:9). Photorealistic, looks like a real lit TV screen
  face-on (no ceiling, no bezel, no camera angle). Danny's app places the screens side by side.
- NO menu text at all: no item names, no prices, no category titles, no logos, no brand names. Leave clean areas for
  them: a heading band, item rows (faint row guides are fine), price spots, and the bottom callout strip.
  The app draws the live names and prices from Supabase on top, so prices are never wrong.
- Food photos: draw the store's real items. Use each product's image_url as the reference for what it looks like.
  One big hero item per screen plus a few small item photos, the way the Subway boards do.
  No image_url? Draw the item from its name and description so it looks like that store's real food.
- Screens per store: one screen per big category, two small categories can share a screen. Order them like the store
  would (deals and meals first, mains, then sides/drinks/desserts). Skip catering and party trays.
- Brand look: the brand's real in-store colors and type feel (Firehouse is not Jersey Mike's is not Subway).
  Local independent stores: a clean board that fits their food (Chinese, deli, pizza, coffee, Puerto Rican...).

3) DATA (Supabase project afnihsdxtisneuyehatw, read only)
  select id, name, description, price, image_url, category from public.products where store_id = '<store_id>' order by category, name;
  select category, sort_order, panel from public.store_categories where store_id = '<store_id>' order by sort_order;
  (store_categories only exists for some stores; otherwise group by products.category)

4) WHERE FINISHED BOARDS GO (do not change any table)
  Upload each screen PNG to bucket menu-images:  fast-casual-boards/<store folder>/board-01.png, board-02.png ...
  Then upload ONE manifest.json to the same folder:
  {"store_id":"<id>","boards":[{"file":"board-01.png","width":1536,"height":1024,
     "title_box":[x,y,w,h],
     "categories":["Deli Classics"],
     "rows":[{"product_id":"<uuid>","name_box":[x,y,w,h],"price_box":[x,y,w,h]}],
     "hero_product_id":"<uuid>","callout_box":[x,y,w,h]}]}
  All boxes are 0-1 fractions of the image width/height (x,y = top-left). One row per product shown on that screen.
  Claude wires the boards into the app from these files. Danny reviews before anything goes live.
