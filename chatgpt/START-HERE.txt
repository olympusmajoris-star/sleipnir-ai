Written 2026-11-26. Everything you need to render the code-built grocery products, without opening the studio.

1) WHAT THE JOB IS
Danny's grocery stores show many products as plain code-drawn pictures. Your job: replace them with real
shelf renders, one store and one aisle at a time, following that store's file below. No store-brand products
are reused across stores; products that already have a render in another store are reused by Danny, not redrawn.

3) DATABASE (Supabase project afnihsdxtisneuyehatw)
REST base: https://afnihsdxtisneuyehatw.supabase.co/rest/v1/
The list to render:
  select * from public.store_info_chatgpt_queue('<store_id>', <shelves 3|4>, <per shelf 2|3>, false, '<AISLE>');
  REST: POST /rest/v1/rpc/store_info_chatgpt_queue  {"p_store":"<store_id>","p_shelves":4,"p_per_shelf":2,"p_include_reusable":false,"p_aisle":"<AISLE>"}
  Returns: aisle, display_type, render_no, layout, shelf, spot_on_shelf, slot, product_id, name, size, price,
           shelf_group, reference_photo, store_brand, shown_now_as, reuse_render_from, upload_path
Where finished renders go:
  storage bucket menu-images, path = upload_path (menu-images/store-renders/<store-slug>/<aisle-slug>/rNNNN.png)
  public.aisle_renders (store_id, aisle, render_no, image_path, width, height, layout, publish_status='draft')
  public.aisle_slots   (store_id, aisle, render_no, slot, product_id, shelf_group, tag_x, tag_y, tag_w, tag_h)
Store info tables (read only):
  store_info_items    one row per product (status 'rendered' or 'code', render_path, crop, universal_id = render elsewhere)
  store_info_core     renders shared by several stores
  store_info_summary  per-store counts
  store_info_aisles   per-store aisle counts
  store_reuse_links   product -> the original render it reuses
  Rebuild after new renders: select store_info_refresh();
Target's own render tables: target_renders, target_render_slots, target_render_spots, view target_render_aisles
